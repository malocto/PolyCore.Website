License packaging

Separate usage from feature unlocks.

For a library product, licensing should be based on how customers embed, distribute and deploy the software—not only on UI feature tiers.

  • Developer seat or team license
  • Runtime / redistribution license
  • Build server and CI usage
  • OEM or embedded deployment
  • Optional format packs with clear third-party terms
Enterprise packaging conceptDraft

Important commercial considerations

01

Third-party codecs

Review licensing, patents, redistribution and commercial-use requirements for every dependency.

02

Usage metrics

Consider per-seat, per-build, per-runtime or volume tiers only where customers can understand and audit them.

03

Support & updates

Define maintenance periods, compatibility guarantees, security fixes and support response levels.

All prices, tiers and license mechanics are illustrative. They should be validated against implementation cost, customer interviews, competing products and legal review before launch.
